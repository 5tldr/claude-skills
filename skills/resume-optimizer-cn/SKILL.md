# 简历优化（国内版）

## 触发条件

当用户需要优化简历、准备求职材料、或进行职业规划时激活。

## 简历结构

### 标准顺序
```
1. 基本信息（必需）
2. 求职意向（必需）
3. 教育背景（必需）
4. 工作经历（必需）
5. 项目经验（推荐）
6. 专业技能（推荐）
7. 荣誉证书（可选）
8. 自我评价（可选）
```

### 应届生顺序
```
1. 基本信息
2. 求职意向
3. 教育背景
4. 实习经历
5. 项目/竞赛经历
6. 校园活动
7. 专业技能
8. 荣誉证书
```

## STAR法则

### 结构
- **S (Situation)**：背景情境
- **T (Task)**：任务目标
- **A (Action)**：采取行动
- **R (Result)**：取得结果

### 示例转换

**原文**（模糊）：
```
负责公司产品运营工作
```

**优化后**（STAR）：
```
负责DAU 50万+的电商App运营（S），
主导用户增长策略制定（T），
通过优化新用户引导流程和设计裂变活动（A），
3个月内新增用户30万，留存率提升15%（R）
```

## 量化技巧

### 数字化表达
| 模糊表达 | 量化表达 |
|----------|----------|
| 负责销售工作 | 年销售额500万，完成率120% |
| 管理团队 | 带领8人团队，人效提升30% |
| 优化流程 | 将处理时间从2天缩短至4小时 |
| 参与项目 | 主导3个核心模块开发 |

### 常用量化维度
- 📊 数量：处理XX条数据、服务XX客户
- 💰 金额：节省XX万成本、创造XX万营收
- ⏱️ 时间：缩短XX%时间、提前X天完成
- 📈 比率：提升XX%、增长XX%、降低XX%
- 🏆 排名：TOP X%、第X名

## 关键词优化

### ATS系统适配
```
1. 提取JD中的关键词
2. 在简历中自然融入
3. 避免图片和特殊格式
4. 使用标准字体
```

### 常见岗位关键词

**产品经理**：
需求分析、用户研究、PRD、原型设计、数据分析、A/B测试、用户增长

**后端开发**：
Java/Python/Go、微服务、分布式、MySQL、Redis、Kafka、Docker、K8s

**数据分析**：
SQL、Python、数据建模、BI工具、用户画像、漏斗分析、归因分析

## 常见问题

### ❌ 避免
- 照片不专业
- 邮箱不正式（如：小可爱@qq.com）
- 自我评价空洞（如：吃苦耐劳、团队精神）
- 工作描述只写职责不写成果
- 技能罗列过多且无重点

### ✅ 建议
- 一页纸原则（应届生）
- PDF格式投递
- 针对不同岗位定制简历
- 突出与岗位相关的经历
- 使用动词开头描述工作
